Prioritized exact-equivalence candidates

1. Sunless scene still pays sun shadow maps and PCF (highest measured GPU ROI).
   src/render/webgpu.ts:128,695,729,762,1320–1343,1384–1428.
   shadowAt result is used only by two direct-sun terms, both multiplied by
   f.sun.w. At exactly zero actual Frame sun intensity, their contribution is zero. Static
   and dynamic SUN shadow preparation/culling/draws can be skipped, and the
   material PCF can be guarded by a uniform zero-sun condition. Spotlights have
   their own maps and must be retained. Do not approximate near-zero sunlight.
   Native proof: frozen source shader/scene with sun=0 and >0, clear/rain/snow,
   lamps, glass/paint and relief; HDR/effects/TAA/final pixels exact at zero;
   first nonzero frame must rebuild fresh static and dynamic sun maps. The
   actual Frame.sun.w must be captured: visual.sunIntensity=0 alone does not
   establish this condition when Game celestial lighting supplies another value.
   Derivative operations in shadowAt require uniform flow; never use a divergent per-pixel
   nl==0 branch as a shortcut. Savings are a hypothesis bounded by the measured
   sun-shadow/PCF work, not an achieved FPS result.

2. Non-caster removal falsely invalidates unrelated static shadow projection.
   src/render/visibility-plan.ts:88–122 indexes Entry by source position. The
   existing WeakMap is used only for the changed-model pass, not identity reuse.
   Remove one posed grass-blade before 128 static walls: exact caster order and
   all camera/light matrices are unchanged, static radiance key and complete
   probe remain bit exact, but staticShadow.staticBuilds 1->2, tests128->256,
   revision1->2. Renderer interprets this as a dirty static shadow and redraws it.
   CPU-only source repro: artifacts/render-roi-cause-probe.ts. No physical tick
   or GPU is needed. Proposed fix is identity-based Entry retention with exact
   per-pass source-order observation and removed-identity retirement, retaining
   invalidation for actual static pose/geometry/deformation/relief changes.
   Required oracle: independent corner culling plus frozen original results over
   non-caster removal/add/reorder, same-ID replacements, mover publication,
   batch changes, static direct pose, stamped deformation and relief changes.
   Static-cache benefit depends on a stationary light; a changed sun matrix is
   still a real cause and must rebuild. No timed win claimed yet.

3. Sky cloud synthesis with exactly zero cloud opacity.
   src/render/lighting.ts:35–44. cloudDrive=smoothstep(.48,.88,humidity)*
   (1-.55*sunlight). At the captured humidity .4425, drive=0. Four noise calls
   (16 hash sin evaluations) and cloud-edge/radiance arithmetic are evaluated
   before color is mixed with opacity0. Uniform drive==0 can omit these only;
   horizon/haze/sun/ground fog must be unchanged. Cost currently mixed into main.
   Proof: native full HDR oracle against frozen old shader for zero, threshold,
   and nonzero cloud drive, night/day and layered fog; isolate sky timing or
   matched frame pair, with profiling disabled in final acceptance.

4. Planar pass runs without any possible receiver.
   src/render/webgpu.ts:1309 computes needsPlanarReflection from asphalt but
   never uses it. Visibility projection, reflection compute requests and draw
   pass remain gated by compiled capability alone (1319,1373,1444). The map is
   read only in the global planar-asphalt branch (825–840). No asphalt receiver
   means no visual contribution. Conservative no-asphalt gate is exact and can
   skip all those stages while retaining a valid bound resource. New asphalt
   must render its map in the SAME submission before reading it, including after
   resize and material/visibility mutation. Current outdoor route has asphalt:
   do not claim its .229ms GPU/.251ms CPU encode is all removable there. Office
   and other receiver-free scenes need a controlled native oracle.

5. Planar asphalt reads seven reflection samples before proving zero weight.
   src/render/webgpu.ts:825–840. roadReflection is computed AFTER the seven
   samples and normal-ripple noise; it is exactly zero for dry no-ice surfaces
   and sufficiently rough wet ones. Compute original weight/in-bounds first,
   then sample only for a nonzero contribution. textureSampleLevel requires no
   implicit derivatives, making this safer than divergent sun-PCF changes.
   Preserve original sample positions/order/weights whenever weight is nonzero.
   Pixel oracle: dry, water/ice/slurry, roughness threshold, slopes/elevated roads,
   bounds edges, rain-on-external surfaces. This alone does not prove the entire
   reflection pass can be skipped: CPU must conservatively cover every surface
   and local field before a pass-wide early-out is correct.

6. Full diagnostic inspection every presented Game frame (CPU, owned by NPC agent).
   Game TheEngineRenderer.render() calls engine.inspect(false) after render(),
   then reads only drawCalls/triangles. false omits just profile; Engine inspect
   (webgpu.ts:1622–1639) still makes multiple object/batch arrays and reductions,
   complete nested visibility/preparation stats, target descriptors, staging sums.
   This lies outside RenderProfiler's submitted frame. Engine public drawCalls
   and triangles already provide those numbers. Full inspect remains available
   on explicit diagnostic/UI cadence; do not hide counters or lower QA coverage.
   Need same Game HUD/stat values and a CPU leaf profile, not estimated savings.

Secondary candidates requiring measurements / larger proof

7. Visibility request overhead: 111 camera draws /1216 candidate instances at
   latest frame, diagnostic visible43; ~29KB visibility uploads. encode() sends
   one112-byte uniform +one20-byte indirect reset per view/batch, then one GPU
   dispatch per nonempty view/batch. Exact request packing could remove hundreds
   of queue calls without removing geometry. Hybrid CPU/GPU cost crossover is
   another possibility, but needs measured threshold and all frustum/fence tests.
   Existing CPU+GPU visibility costs are real; no guessed percentage claimed.

8. Hidden sky fragment shading. Sky currently draws first across the full
   viewport with depthCompare always, then opaque objects overwrite it. Drawing
   it after opaques at far depth could retain only uncovered samples. Requires
   exact MRT clear/velocity/normal semantics, far/log-depth and edge oracle.
   Cost folded into main, and cloud-zero gate is a smaller first experiment.

9. Bloom Gaussian is already separable at half resolution: 37 taps per axis,
   total blur mean .408ms. Paired linear filtering can reproduce the mathematical
   kernel with 19 taps, same extent/weights. Floating interpolation and operation
   order may alter quantization; requires native impulse/bright-edge/reference
   HDR proof before acceptance. Do not reduce the radius/sample-quality preset.
   WGSL compiler may fold loop exp values already; source appearance alone is
   not evidence that a constant-table rewrite saves time.

10. Empty transparent stage copies the entire opaque HDR texture even when
    there are no visible transparent entities and no snowfall. Exact aliasing or
    copy elimination would save this stage in such scenes; current outdoor trace
    had four camera-transparent objects, so no guaranteed gain in it. Glass must
    retain the original opaqueScene refraction source and transparency order.

11. CPU fallback instancing repacks/uploads every matrix each frame; native
    Game uses GPU-owned batches and latest CPU-fallback instances=0. Extend the
    existing exact dirty-range InstanceStream scheme only after profiling an
    actual CPU fallback workload. Same transforms and history settle are required.

12. prepareShadowBatches allocates temporary Float32 arrays then exact-compares
    against resident data. It already skips unchanged GPU upload; reuse bounded
    scratch/dirty rows may reduce CPU allocation. Main GPU shared shadow batches
    already avoid much of this; separate allocation profile before changing it.

Areas audited where current code already avoids obvious waste

- Material-class pipelines specialize the common shader, opaque depth prepass
  was proved against a native frozen oracle already; no blanket material cuts.
- GPU camera instance streams upload only exact changed data and settle previous
  model once; static model-history entries retain storage by entity identity.
- Surface textures use authoritative field revisions; uniforms/staging retained.
- Environment map worker has one active and one latest request, bounded four-map
  cache, reset-generation rejection and atomic completed publication. Physical
  static radiance changes must remain causes. Old same-scene source membership
  alone does not reset the map cache.
- Current Game near-grass is posed immediately by setVisualTransform, so it is
  a render mover and is excluded from static-only distant radiance. It also has
  castsRenderShadow=false. The CPU repro verifies this exact causal distinction.
  Generic small static geometry below the probe's radius .08 cutoff still enters
  the cause hash; false invalidations exist in principle, but filtering these
  requires scale/direct-edit-safe parity with the actual probe eligibility.
- Environment CPU mean .153ms and light-grid mean .070ms are lower priority than
  culling/preparation. No longer probe cadence, atmosphere quantization or reduced
  lighting/shadow resolution is proposed. Existing large frozen mesh bounds are
  cached; mutable nested inputs remain observed.
- Screen effects already reject sky before AO/GI/SSR, zero receive/emit before
  neighbor HDR reads, and rough/nonreflective material pixels before SSR marching.
  Those existing contributions need original pixel oracles before more shortcuts.
- Fog already rejects zero density, empty lamp ranges, zero housing emission and
  duplicate light samples. Spot shadows already select bounded two active lamps.
- Motion blur, probe and spot shadows were inactive in this reference; additional
  night/headlight/car/flight captures are required before ranking their active cost.
