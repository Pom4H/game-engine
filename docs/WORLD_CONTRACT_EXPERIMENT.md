# World IR: первый проверяемый контракт

## Что реализовано

Это экспериментальный **диалект аффинного резервуара**, а не универсальный язык физики.
Существующие `.world → WSCN → Scene` и World Interaction IR остаются без изменений.
В `compiler/examples/world-contract.rs` находится отдельный эксперимент существующего crate `worldc`:
контролируемый RU/EN-текст → проверка размерностей и ограничений → канонический JSON.
Пример не меняет выбор бинарника для существующих `cargo run --manifest-path compiler/Cargo.toml`.

`src/world-ir/tank-contract.ts` независимо проверяет JSON, в том числе полученный от LLM.
Насос и резервуар исполняются в **существующем EngineKernel**: два варианта одного `tank.flow`
slot возвращают переходы, а runtime фиксирует результат в одном авторитетном состоянии.
Нет второго состояния для быстрого режима. Независимые экземпляры создаются только в сравнительных тестах.
Контракт пока не прикреплён к `SceneSpec`, 3D-геометрии, реальному PLC или причинному журналу Scene.

## Один смысл, два текста

`examples/world-contracts/tank-en.wcontract` и `tank-ru.wcontract` должны дать идентичный JSON,
совпадающий с `tank.json`. Это контролируемый синтаксис с ключевыми словами, не понимание произвольной речи.
Одно поле занимает одну строку, число и единица разделены пробелом; комментарий начинается с `#`.
Все поля обязательны; повторения, неизвестные поля, неподдерживаемые модальности и неверные единицы отклоняются.

```text
contract FillTank {
capacity: 200 L
observed: 70 L
error: 1 L
source: level_sensor
at: 0 s
law: constant-inflow-no-outflow
flow: 5 L/s
start_delay: 0 s
goal: reach 120 L within 30 s
}
```

Единицы объёма: L/л, mL/мл, m3; расхода: L/s, л/с, mL/s, мл/с, m3/s;
времени: s/с, ms/мс, us. Не более шести знаков после точки; значение должно точно
представляться в микролитрах, микролитрах/секунду либо микросекундах.
Никакого округления неизвестных величин или неявных значений по умолчанию.

## Границы смысла

Измерение `70 ± 1 L` — ограничение на знание, а не присваивание `volume = 70`.
Конструктор требует явно заданное начальное состояние симуляции в этом интервале.
Источник и время наблюдения сохраняются в контракте. Пока нет объединения нескольких наблюдений,
модели старения данных или интеграции с датчиком.

`reach` означает: цель хотя бы однажды достигнута не позднее срока относительно `observation.atUs`.
Это не `maintain`, не разрешение и не команда запуска. Уже достигнутая цель остаётся выполненной
после внешнего уменьшения объёма. Позднее достижение не исправляет пропущенный срок.

Запрос пуска требует политики авторизации хоста (по умолчанию отказ). Сам запрос создаёт
`start-requested`, но `running` меняется только при исполнении явно объявленной задержки
идеализированного привода. Это симулируемое подтверждение, а не доказательство запуска оборудования.
Отказ отменяет ожидающий пуск. Политика авторизации здесь не заменяет аутентификацию сервера.

## Исполнение и точность

Закон: постоянный неотрицательный приток, нулевой отток; ни давления, ни волн, ни сжимаемости.
На интервале с неизменным состоянием насоса:

```text
V(t + dt) = V(t) + q * dt, если насос запущен
V(t + dt) = V(t), иначе
```

Время хранится целыми микросекундами, объём — целыми пиколитрами, расход — целыми микролитрами/секунду.
Поэтому произведение `q * dt` сразу даёт пиколитры и не теряет дробный остаток между шагами.
События порогов относятся к первой подходящей точке микросекундной сетки; относительно
непрерывного времени пересечения возможна задержка менее 1 us. Это не обещание непрерывной точности времени.

`stepped` проходит интервал шагами не более 1 ms с разрезанием на событии пуска.
`event-driven` пропускает пустые микрошаги, сохраняя аффинный закон, будущий пуск и время цели.
Оба режима исполняются через заранее скомпилированные варианты EngineKernel.
Это **два способа исполнения одной точной скалярной модели**, а не подробная и приближённая гидродинамика.
Число шагов не следует интерпретировать как ускорение графического движка или измеренный рост FPS.

Переполнение не зажимается к `capacity`: переход отклоняется целиком, без частичного изменения
состояния, журнала и счётчиков. При монотонном притоке проверка конечного объёма покрывает промежуточные значения.
Длительность одного вызова ограничена 100 s; журнал хранит последние 256 событий с явным счётчиком потерь.

## Что гарантирует сертификат

Сертификат относится только к `volume`, `goal-event`, `pump-events` на микросекундной временной сетке.
Он содержит модель, ревизию, начало, конечный горизонт, нулевую ошибку объёма и вид основания:
`analytic-affine-lattice-and-tests`. Это математическое обоснование плюс тесты, **не машинно проверенная теорема**.
Для постоянного q сумма произведений q*dt равна q умножить на суммарное время: отсюда эквивалентность объёма.
В обоих исполнениях пуск разбивает интервал одинаково; первый момент цели вычисляется целочисленным ceil.

Выдача отклоняется для неподдерживаемых наблюдаемых величин или горизонта, нарушающего вместимость.
Изменение расхода, внешний объём, запрос действия и отказ изменяют ревизию.
Обычное движение внутри допустимого горизонта не изменяет ревизию: сертификат можно использовать
после нескольких шагов и переключений режима. Потерянный pending-start не восстанавливается догадкой:
он остаётся частью общего состояния.

Состояние хранится в JS private fields; снимки и спецификация заморожены.
Сертификат другого экземпляра, его JSON-копия или подделка отклоняются через локальный WeakSet.
Эти сертификаты не сериализуются для переноса между процессами; распределённые доказательства и репликация не реализованы.
Произвольные сторонние законы не получают гарантии автоматически.

## Проверяемое следствие

При показании 70 ± 1 L, притоке 5 L/s, пуске без задержки и запросе в момент наблюдения:
через 10 s получается 119–121 L. Гарантированное достижение 120 L — через 10.2 s.
`earliestGuaranteedReachUs` возвращает этот **условный расчёт**, а не выдаёт разрешение или команду.
При задержке привода 0.2 s соответствующая граница сдвигается до 10.4 s.

## Запуск

Из корня репозитория:

```sh
cargo test --manifest-path compiler/Cargo.toml --example world-contract
cargo build --manifest-path compiler/Cargo.toml --example world-contract
cargo run --manifest-path compiler/Cargo.toml --example world-contract -- examples/world-contracts/tank-en.wcontract
bun run build
```

PowerShell:

```powershell
$env:WORLD_CONTRACT_COMPILER = "$PWD\compiler\target\debug\examples\world-contract.exe"
node --test test/world-contract.test.mjs
node tools/world-contracts/proof.mjs
```

POSIX:

```sh
export WORLD_CONTRACT_COMPILER="$PWD/compiler/target/debug/examples/world-contract"
node --test test/world-contract.test.mjs
node tools/world-contracts/proof.mjs
```

Без Rust можно проверить только JSON → runtime: `node tools/world-contracts/proof.mjs --json-only`.
Такой отчёт явно помечает RU/EN-проверку и независимый Rust-эталон как НЕ выполненные.
Обычный набор Node-тестов пропускает три межъязыковых теста без переменной окружения;
специализированный CI задаёт её обязательно, а отсутствующий бинарник считается ошибкой.

## Протокол исследования

Есть 10 Rust-тестов синтаксиса/единиц/неоднозначностей и 20 Node-тестов, в том числе
128 детерминированных комбинаций неокруглённых параметров. Rust `--oracle` использует
независимую замкнутую формулу, а не цикл интегратора или сгенерированный из TypeScript код.
Отчёт `artifacts/world-contracts/proof.json` фиксирует commit, runner, версии, область проверки,
начальные границы, события и число сегментов. Обе стратегии обязаны совпадать до сравнения стоимости.

CI `.github/workflows/world-contracts.yml` использует только `[self-hosted, Windows, X64]`.
Межъязыковые тесты обязательны; файл отчёта также печатается в лог и job summary.
Необязательная загрузка артефакта не подменяет обязательные тесты.

Пока НЕ измерены: успешность LLM-формализации, преимущество над TypeScript по трудозатратам,
полноценный динамический физический LOD, WASM-ускорение этого домена, GPU/FPS и междоменная сцена
«удар → звук → реакция агента». Этот прототип не позволяет заявлять такие результаты.
