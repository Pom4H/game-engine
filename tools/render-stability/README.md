# Native render stability regression

Build the engine, then run `node tools/render-stability/verify.mjs` with Node 22 or newer. Chrome or Edge must expose a native WebGPU adapter; software and anonymous adapters fail the check. Set `CHROME_PATH` to choose a browser. Optional `RENDER_STABILITY_WIDTH` and `RENDER_STABILITY_HEIGHT` default to 480 by 270.

The harness checks actual GPU capture, copy, GGX filtering and material passes across static, camera-motion and probe-motion frames. Four probe faces are captured on the first frame and the remaining two on the next. Only completed sweeps publish their image and capture origin. A compute readback samples every mip-zero texel of all six published cube faces through the existing texture binding: partial sweeps must leave them bit-for-bit unchanged, completed static sweeps must agree within 0.000001, and completed sweeps from a moved origin must change the reflected radiance. These checks also cover simultaneous camera movement and a pending new probe origin. Every HDR, effects, TAA and planar-reflection pixel is checked for finite values and the images must contain visible radiance. The production TAA shader also runs the existing coordinate and poisoned-input checks.

Results are saved to `artifacts/render-stability/report.json` and `native-render.png`. CPU timings describe this small correctness fixture and include pipeline warmup; they do not establish game FPS. The browser uses a fresh temporary profile and closes after the run.

Run `node tools/render-stability/physics-ray-cache.mjs` separately to compare cached and uncached compound wheel-ray geometry. It checks identical hit counts and summed coordinates while exercising stationary and moving bodies at three population sizes. Results are saved to `artifacts/render-stability/physics-ray-cache.json`. This isolated workload measures query cost rather than server tick time.

`node --test test/temporal-batch-updates.test.mjs` compares production GPU instance preparation against the frozen preceding full-scan algorithm across 60 temporal, compact and lifetime states. Both the live stream bytes and upload ranges must match exactly; a separate upload-failure case checks recovery. Model lookup counters describe removed bookkeeping and do not establish an FPS gain. Native pixel/TAA validation after this optimization is recorded in `docs/render-evidence/temporal-instance-updates-20261018.json`.

`node --test test/gpu-batch-key-lifetime.test.mjs` checks compact batch keys against actual GPU mesh deduplication, material equality, material-map pruning and evicted mesh generations. Collection-inclusive allocation evidence and its limits are recorded in `docs/render-evidence/gpu-batch-key-allocation-20261018.json`; the isolated result does not establish game FPS.
