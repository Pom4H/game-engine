# Конструктор персонажа

Живой редактор персонажа на штатном WebGPU-рендерере Game Engine.

## Запуск

Из корня репозитория:

~~~sh
bun install --frozen-lockfile
bun run characters
~~~

Откройте **http://localhost:4174/characters/**. Команда сама собирает TypeScript.
Порт меняется переменной PORT. Сервер по умолчанию слушает только 127.0.0.1.

## Управление

- **Тело:** рост 150–205 см, комплекция, плечи, бёдра, длина торса, рук и ног.
- **Одежда:** парка, рабочая куртка или свитер; джинсы или карго; ботинки или кеды; шарф и цвета.
- **Лицо:** спокойное выражение, скептический взгляд или усмешка; растрёпанные волосы, короткая стрижка или без волос; цвет кожи и волос.
- **Позы:** стоя, ходьба на месте, рука вперёд и руки в стороны. Кнопка воспроизведения включает ходьбу.
- **Камера:** перетаскивание, колесо или жест двумя пальцами; фиксированные виды со всех сторон и крупный план лица. На сфокусированном canvas работают стрелки и +/−.
- **Код:** скачать JSON или готовый TypeScript scene.ts; применить отредактированный JSON либо открыть файл.
- **Снимок:** PNG непосредственно из canvas движка.
- **История:** Ctrl/Cmd+Z и Ctrl/Cmd+Shift+Z, не более 30 шагов. Один жест ползунка составляет один шаг.
- Параметры последнего персонажа сохраняются в браузере. Некорректный импорт не изменяет модель.

Готовые образы: **Скептик**, **Механик**, **Наблюдатель**.

## Использование в сцене

~~~ts
import {
  compileCharacter,
  DEFAULT_CHARACTER_SPEC,
  type SceneSpec,
} from '@rom4/game-engine';

const actor = compileCharacter({
  ...DEFAULT_CHARACTER_SPEC,
  id: 'resident',
  body: { ...DEFAULT_CHARACTER_SPEC.body, height: 1.88 },
});

export default {
  version: 1,
  entities: actor.entities,
  animation: {
    walkers: [{ ...actor.walker, root: [3, 0, 5], speed: 0.7 }],
  },
} satisfies SceneSpec;
~~~

compileCharacter возвращает нормализованную спецификацию, сущности, WalkerSpec
и измерения модели. Все части renderOnly; библиотека не создаёт невидимый
физический манекен и не добавляет вторую симуляцию.

Фабрика доступна также из @rom4/game-engine/browser.
Исходные модули: src/characters/character.ts, face.ts и pose.ts.

## Общие размеры и владение позой

humanoidMeasurements разрешает пропорции в метры. Эти размеры используются
скелетом, IK, одеждой и привязками. Рост — расстояние от подошвы до фактической
верхней вершины волос, с учётом выбранных пропорций и причёски.

Одежда имеет замкнутую геометрию со складками и нормалями поверхности. Рукава и
брючины привязаны к реальным концам костей. Кисти сохраняют размер и следуют
ориентации предплечья через HumanoidBinding.orientFrom.

В обычной сцене позой владеет AnimationSystem. В редакторе вместо маршрута
установлена одна проекция sampleCharacterPose: она выдаёт суставы для выбранной
позы и времени, затем bindHumanoid публикует все визуальные transforms.
renderMovers объявлены одним плагином редактора. Камера и поза предпросмотра
не изменяют сохранённый CharacterSpec.

Голова использует непрерывную CC0-сетку, доработанную в ветке сцены чая,
плюс геометрические волосы и брови. Источник и лицензия:
[face-reference.md](../../licenses/face-reference.md).
Референс в интерфейсе — приложенное пользователем изображение; это направление
для стилизации, не фотографическая реконструкция.

## Отдельный HTML

~~~sh
bun run characters:bundle
~~~

Создаётся artifacts/character-creator.html: приложение, движок, CSS и референс
в одном файле. Сеть для геометрии и материалов не нужна.
Откройте его в браузере, предоставляющем WebGPU для локальных файлов, либо
раздайте по HTTPS/localhost. Отсутствие WebGPU отображается в интерфейсе;
программный рендер не подменяет аппаратное доказательство.

## Проверка

~~~sh
bun run typecheck
bun run build
node --test test/character*.test.mjs test/humanoid-proportions.test.mjs test/animation.test.mjs
node tools/character-creator/capture.mjs
~~~

Capture использует установленный Chrome, при необходимости CHROME_PATH.
Workflow **Character Creator** сначала выполняет контракты и проверку типов,
затем снимает редактор на аппаратном GPU macOS runner. Он проверяет настоящий
WebGPU adapter, свежий исходный SHA, смену роста и одежды через элементы
управления, JSON roundtrip, разные виды и мобильную компоновку.

Артефакт workflow содержит отдельный HTML, PNG и
character-creator-evidence.json с адаптером, исходным SHA, состояниями персонажа,
размерами и хешами PNG. CHARACTER_ALLOW_SOFTWARE=1 доступен только для явно
обозначенных локальных проверок взаимодействия; hardwareProof остаётся false.
